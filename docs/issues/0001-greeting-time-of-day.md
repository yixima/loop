## 背景（なぜやるのか）

現在の `greet()` は時刻に関係なく常に「こんにちは」を返す。
社内ツールの通知文で使われており、深夜のバッチ通知にも「こんにちは」と出てしまい、
受け取った人が「これは自動送信か手動送信か」を判断しづらいという声が出ている。
時間帯が文面に現れれば、送信タイミングが一目で分かる。

## ゴール（何が達成されたら終わりか）

`greet()` が、渡された時刻（または現在時刻）に応じて「おはようございます」「こんにちは」「こんばんは」を
使い分けられる状態。

既存の呼び出し側は **引数を足さなくてもそのまま動く**（`greet(name)` が例外なく呼べる）こと。
ただし **返す挨拶は時刻によって変わる**。これは後方互換の破壊ではなく、本課題の目的そのものである。
深夜のバッチ通知に「こんにちは」と出るのを直すのが狙いなので、
呼び出し側を書き換えなくても改善が効くことを優先する。

## 受け入れ条件（機械が判定できる形で）

- [ ] `greet("山田", hour=5)` 〜 `greet("山田", hour=10)` が `"おはようございます、山田さん"` を返す
- [ ] `greet("山田", hour=11)` 〜 `greet("山田", hour=17)` が `"こんにちは、山田さん"` を返す
- [ ] `greet("山田", hour=18)` 〜 `greet("山田", hour=4)`（日をまたぐ）が `"こんばんは、山田さん"` を返す
- [ ] `hour` が 0〜23 の範囲外なら `ValueError` を送出する
- [ ] `hour` が `int` 以外（`"5"` / `5.0`）なら `TypeError` を送出する
- [ ] `hour` が `bool`（`True` / `False`）なら `TypeError` を送出する。
      Python では `bool` は `int` のサブクラスなので、明示的に拒否しないと
      `greet("山田", hour=True)` が 1時として静かに通り、誤った挨拶を返してしまう
- [ ] `greet("山田", 5)` のような位置引数での指定は `TypeError` になる（キーワード専用）
- [ ] `hour` を省略した場合は現在時刻を使う（テストでは時刻を注入して検証すること。実時刻に依存するテストを書かない）
- [ ] `name` の検証仕様は変わらない（空文字・空白のみは `ValueError`、非 str は `TypeError`）
- [ ] 既存 `tests/test_greeting.py` の5件は、実時刻に依存しないよう `hour` を明示する形に
      **更新してよい**。ただし削除・スキップ・アサーションの緩和は禁止で、件数を減らさないこと
- [ ] `hour` 省略時の挙動（現在時刻を使う）を検証するテストを **新規に追加する**。
      既存テストから省略パスの検証が消えるため、ここを飛ばすとデフォルト挙動が無検証になる
- [ ] 上記の型・範囲・キーワード専用の各仕様に、それぞれ対応するテストが存在する。
      **仕様をテストで固定しないと、冗長に見える検証は次のリファクタリングで削られる**
- [ ] `./scripts/verify.sh` が終了コード 0 で完了する

## 制約・前提

- 対象ファイルは `src/loopdemo/greeting.py` と `tests/` のみ
- 既存の引数 `name` のシグネチャと例外仕様（空文字で `ValueError`、非str で `TypeError`）は変えない
- `hour` はキーワード専用引数として追加し、位置引数を増やさない
- 境界値（4/5、10/11、17/18）はすべてテストで押さえること
- 時刻の取得はテストから差し替え可能にすること。ただしプロダクションコードに
  テスト専用の引数やフラグを足さないこと（原則3: 基盤部分に仮のデータを使わない）
