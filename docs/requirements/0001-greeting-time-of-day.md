## 1. 解決したい問題

**事実（コードとして確認できること）**

- `src/loopdemo/greeting.py:21` は時刻に関係なく常に `"こんにちは、{name}さん"` を返す。
- 公開APIは `greet` の1つだけ（`src/loopdemo/__init__.py:8-10`）。
- リポジトリ内で `greet()` を呼んでいるのは `tests/test_greeting.py` だけ（`grep -rn "greet"` で確認）。

**課題ファイルに書かれている背景（このリポジトリ内では検証できない前提）**

- 社内ツールの通知文で使われており、深夜のバッチ通知にも「こんにちは」と出てしまう。
- 受け取った人が自動送信か手動送信かを判断しづらい。時間帯が文面に出れば送信タイミングが分かる。

**設計時に判明した矛盾と、その決着（重要）**

課題の受け入れ条件には次の2つが同時に書かれていた。

1. 「`hour` を省略した場合は現在時刻を使う」
2. 「既存の `test_greeting.py` の5件が1件も変更されずに通り続ける」

既存テストは `greet("山田") == "こんにちは、山田さん"`（`tests/test_greeting.py:14,17`）を期待している。
`hour` 省略時に現在時刻を使う実装にすると、**このテストは 11〜17 時台にしか通らない**。
実装が正しくても、`./scripts/verify.sh` を実行した時刻によって赤くなったり緑になったりする。

**→ 2026-08-21、人間の決定により「案B」を採用した。**
`tests/test_greeting.py` の該当2件を、時刻を明示的に注入する形（`hour=12`）に書き換えることを許可する。
これに伴い、受け入れ条件2は**取り下げ**、後方互換の定義を 3章 F9〜F11 に置き換える（詳細は 6章）。

## 2. 利用者とユースケース

| 利用者 | やりたいこと | 現状の困りごと |
|---|---|---|
| 社内ツールの通知文を組み立てる開発者 | 送信時刻に合った挨拶語を文面に入れたい | 常に「こんにちは」で、深夜通知でも時間帯が伝わらない |
| 通知を受け取る社員 | 自動送信か手動送信かを一目で判断したい | 文面から送信タイミングが読み取れない |
| 既存の呼び出し側（`greet(name)` だけを使っている箇所） | 何も変更せずに今までどおり呼べること | 引数が増えて呼び出しが壊れると影響範囲が広がる |
| テストを書く開発者 | 時刻依存で落ちないテストにしたい | 現在時刻を使う実装は、そのままだと実行時刻でテスト結果が変わる |

## 3. 機能要件

「受け入れ条件」の列は、設計書6章のテストIDと1対1で対応する。

| # | 要件 | 優先度 | 受け入れ条件（検証可能な形） |
|---|---|---|---|
| F1 | `hour` が 5〜10 のとき「おはようございます」を使う | must | `greet("山田", hour=h)` が h=5,6,7,8,9,10 のすべてで `"おはようございます、山田さん"` を返す → **T1** |
| F2 | `hour` が 11〜17 のとき「こんにちは」を使う | must | `greet("山田", hour=h)` が h=11..17 のすべてで `"こんにちは、山田さん"` を返す → **T2** |
| F3 | `hour` が 18〜23 および 0〜4 のとき「こんばんは」を使う（日またぎ） | must | `greet("山田", hour=h)` が h=18..23 および h=0..4 のすべてで `"こんばんは、山田さん"` を返す → **T3** |
| F4 | 境界値 4/5、10/11、17/18 が仕様どおりの側に入る | must | h=4→こんばんは, 5→おはようございます, 10→おはようございます, 11→こんにちは, 17→こんにちは, 18→こんばんは → **T4** |
| F5 | `hour` が 0〜23 の範囲外なら `ValueError` | must | `greet("山田", hour=-1)`, `hour=24`, `hour=100` が `ValueError` → **T5** |
| F6 | `hour` が int 以外なら `TypeError`。`bool` も拒否する | must（決定: Q2） | `greet("山田", hour="5")`, `hour=5.0`, `hour=True`, `hour=False` が `TypeError` → **T6** |
| F7 | `hour` 省略時は現在時刻の「時」を使う。テストは実時刻に依存しない | must | 時計を 23時/3時/7時/13時に固定した状態で `greet("山田")` がそれぞれ こんばんは/こんばんは/おはようございます/こんにちは を返す → **T7** |
| F8 | 検証順序は `name` → `hour`。`name` 側の例外が優先される | must | `greet(None, hour=99)` は `TypeError`、`greet("", hour=5)` は `ValueError` → **T8** |
| F9 | 後方互換①: `name` の例外仕様が変わらない | must | `greet("")`・`greet("   ")` が `ValueError`、`greet(None)` が `TypeError`（いずれも `hour` 未指定でも指定時でも同じ） → **T9** |
| F10 | 後方互換②: シグネチャ互換。`greet("山田")` が引数1つのまま例外なく動き、`name` の strip も維持される | must | `greet("山田")` と `greet("  山田  ")` が例外を出さず、`"（おはようございます\|こんにちは\|こんばんは）、山田さん"` のいずれかに一致する（実行時刻に関係なく成立） → **T10** |
| F11 | 既存テストの変更は許可された2件のみ。残り3件は無変更で通る | must（決定: Q1=案B） | ベース（merge-base）と比べた `tests/test_greeting.py` の増減行が計4行（`-` 2行 / `+` 2行）で、かつ書き換え後の5件すべてが pass → **T11**。確認コマンドは表の直後の注記を参照 |
| F12 | `hour` はキーワード専用引数（位置引数では渡せない） | must（決定: Q3） | `greet("山田", 5)` が `TypeError` → **T12** |

>
> ```bash

## 4. 非機能要件

- **性能**: 分岐と文字列生成のみ。追加のI/Oは `datetime.now()` の1回だけ。性能上の要求はない。
- **セキュリティ**: 外部入力の保存・送信なし。追加の考慮事項なし。
- **可用性 / 運用**: 追加依存パッケージを入れない（標準ライブラリ `datetime` と `unittest.mock` のみ）。
  `pyproject.toml:5` の `requires-python = ">=3.10"` に合わせ、型注釈は `int | None` を使う（`typing.Optional` は ruff の `UP` 規則に抵触する）。
  `pyproject.toml:12` の `line-length = 100`、`ruff format` に準拠すること。
  **テストは pytest 固有の機能に依存させない**（`scripts/verify.sh:102-106` は pytest が無い環境では
  `python -m unittest discover` にフォールバックするため、どちらのランナーでも同じ結果になること）。
- **互換性（既存機能を壊さないこと）**:
  - `greet(name)` の呼び出し形をそのまま維持する（引数追加はキーワード専用・デフォルト値ありで行う）→ F10
  - `name` の例外仕様（空文字/空白のみ → `ValueError`、非str → `TypeError`）とメッセージを変えない → F9
  - 戻り値の形式 `"{挨拶語}、{name}さん"` を維持する（`name` は前後の空白を除去）
  - 公開API `__all__ = ["greet"]` を増やさない

## 5. スコープ外

- タイムゾーンの扱い（ローカル時刻のみ。`datetime.now()` のローカル時刻をそのまま使う）
- 日本語以外へのローカライズ
- `greet()` 以外の**公開**関数の追加・変更（`__all__` を増やさない）
- CLI や API の追加
- 挨拶語や時間帯区分の設定ファイル化・外部からの差し替え機構
- 通知バッチ側（このリポジトリ外）の変更
- `tests/test_greeting.py` の許可された2件以外への変更（テストの追加・削除・整形を含む）

- [x] **Q1（ブロッカー）**: 「`hour` 省略時は現在時刻を使う」と「既存テスト5件を1件も変更しない」が両立しない件。
  - **決定: 案B を採用**。`tests/test_greeting.py` の次の2件を、時刻を明示注入する形に書き換えることを許可する。
    - `test_通常の名前で挨拶文を返す` → `greet("山田", hour=12) == "こんにちは、山田さん"`
    - `test_前後の空白は取り除かれる` → `greet("  山田  ", hour=12) == "こんにちは、山田さん"`
    - 残り3件（空文字 `ValueError` / 空白のみ `ValueError` / 非str `TypeError`）は**無変更**のまま通ること。
  - **取り下げた受け入れ条件**: 課題ファイルの「既存の `test_greeting.py` の5件が **1件も変更されずに** 通り続ける」。
    - 取り下げの理由: この条件を維持したまま「省略時は現在時刻」を実装すると、テストの成否が実行時刻に左右され、
      `./scripts/verify.sh`（唯一の停止条件）が信頼できなくなるため。
    - 代替: 後方互換の意味を「シグネチャ互換（F10）」と「`name` の例外仕様の不変（F9）」に置き換え、
      いずれも**新規テスト**（T9・T10）で担保する。加えて、既存ファイルへの変更が許可された2行に限られることを F11 で機械的に確認する。
  - **不採用**: 案C（`tests/conftest.py` で時計を固定）。pytest 経由でしか効かず、`verify.sh` の unittest フォールバックで
    再び実行時刻に依存するため。案D（省略時は「こんにちは」固定）も、課題の主目的を満たさないため不採用。
- [x] **Q2（確認）**: `hour` が int 以外のときの振る舞い。
  - **決定: `TypeError`。`bool` も拒否する**。`isinstance(hour, bool)` を先に弾いてから `isinstance(hour, int)` を見る。
    `greet("山田", hour=True)` は `TypeError`（黙って1時として扱わない）。→ F6 / T6
- [x] **Q3（確認）**: `hour` をキーワード専用にしてよいか。
  - **決定: キーワード専用**。`def greet(name: str, *, hour: int | None = None) -> str`。
    `greet("山田", 5)` は `TypeError`。→ F12 / T12
